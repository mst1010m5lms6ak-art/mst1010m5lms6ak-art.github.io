### 1-1. Web公開手順（そのまま配信可能・ビルド不要）

1. **GitHub Pages（ブランチ直接配信）**
   - リポジトリ直下に `index.html` と `.nojekyll` が配置済み。
   - GitHub リポジトリの `Settings` → `Pages` → `Source: Deploy from a branch` → `Branch: main` / Folder: `/ (root)` を選択するだけで公開完了。
2. **GitHub Pages（GitHub Actions 自動デプロイ）**
   - `.github/workflows/deploy-pages.yml` 同梱済み（`main` push または手動 `workflow_dispatch` で `path: '.'` を自動配信）。
   - `Settings` → `Pages` → `Source: GitHub Actions` を選ぶだけで自動公開。
3. **Cloudflare Pages**
   - リポジトリ連携時、Framework preset: `None`、Build command: **空欄**、Build output directory: `.`（または `/`）に設定してデプロイ。

### 1-2. 将来の Capacitor iOS アプリ化手順

本アプリは最初から Capacitor 互換規約（全パス相対 `./`、`global.Capacitor` 検出時の SW 登録ガード、`viewport-fit=cover` + `env(safe-area-inset-*)` 完全対応）を満たしています。

1. **別ディレクトリ（またはワークスペース外）で Capacitor プロジェクト作成**（本リポジトリの100ファイル上限を圧迫しないため `node_modules` や `ios/` は分離推奨）:
   ```bash
   npm init -y
   npm install @capacitor/core @capacitor/cli @capacitor/ios
   npx cap init "はちゃめちゃ世界" "com.example.hachamechasekai" --web-dir www
   ```
2. **`www/` へ配布アセットをコピー（規約）**:
   - コピー対象: `index.html`, `manifest.webmanifest`, `css/`, `js/`, `assets/`（※ `docs/`, `.github/`, `.nojekyll` は不要。`sw.js` は同梱しても `js/ui/app.js` の `if (location.protocol === 'file:' || global.Capacitor) return;` ガードで自動無効化される）。
   - すべてのアセット参照は必ず相対パス `./` を維持すること（絶対パス `/` に変更禁止）。
3. **iOS プロジェクト同期＆Xcode ビルド**:
   ```bash
   npx cap add ios
   npx cap sync ios
   npx cap open ios
   ```
   - Xcode 側で `Signing & Capabilities` を設定し、ステータスバー重なり・ホームインジケータ余白（`env(safe-area-inset-top/bottom)`）と `position: fixed; inset: 0;` の固定挙動を実機確認する。

## 2. 絶対厳守の禁止事項一覧（ゼロ容認チェックリスト）

次回以降の改修では、以下の禁止事項を**1項目たりとも絶対に破ってはならない**。改修後・公開前の監査で全項目をチェックすること。

### ゲームデザイン禁止事項
- [ ] **ガチャ完全禁止**: 確率課金・ランダムキャラ排出・ガチャ石の概念を導入しない（キャラ加入は確定4ルートのみ）。
- [ ] **実時間タイマー・日課系完全禁止**: デイリー／ウィークリー／マンスリー任務、スタミナ自然回復、実時間経過待ち遠征、リアルタイム放置報酬を一切作らない（別働隊は戦闘勝利数連動のみ）。
- [ ] **PvP・ランキング完全禁止**: 対人戦・非同期アリーナ・オンラインランキングを作らない（オフラインソロ PvE 完結）。
- [ ] **オプション系ハクスラ完全禁止**: 装備へのランダムサブステータス付与・厳選要素を入れない（装備の個体差は「品質 1〜100」のみ）。
- [ ] **レベルシステム完全禁止**: キャラレベル・経験値バー・レベル上限解放を作らない（成長は固定5軸のみ）。
- [ ] **装備強化（`+1` / `+10` 等）完全禁止**: 装備自体を強化・鍛錬・合成する機能を作らない（品質掘り＋セット組み換えのみ）。
- [ ] **図鑑ステータスボーナス完全禁止**: 図鑑収集率や登録数によるHP/攻撃等の能力補正を一切付けない（図鑑は純粋な観賞・確認用）。
- [ ] **開発メタ発言・設定そのまま説明文禁止**: UI文言・ロア・ヘルプ・トースト等に「実装済み」「Phase」「仕様上」「ランダムオプション無し」「テスト用」などの開発者メタ表現や内部設定の直書きを出さない。

### ビジュアル・レンダリング・パフォーマンス禁止事項
- [ ] **キャライラスト＆SVG完全禁止**: `<img>` キャラ立ち絵・ドット絵・`<svg>` タグ・`data:image/svg+xml` を一切使用しない（アイコン PNG 3種は PWA/ファビコン専用。ゲーム画面は純CSSの紋章・色・模様・タイポグラフィ・絵文字で構成）。
- [ ] **`backdrop-filter: blur` / `filter: drop-shadow` 完全禁止**: モバイル WebView / Safari でのフレーム落ち防止のため一切使わない。
- [ ] **`.style.width` によるゲージアニメーション禁止**: HP・防護壁・ATB・DPSバーは必ず `transform: scaleX(...)`（`HS.Anim.setGauge` / `setHpGauge`）のみで GPU 描画すること。
- [ ] **最小 `10px` 未満フォント禁止**: 全 CSS の `font-size` は必ず `10px` 以上（入力系 `<input>`/`<textarea>`/`<select>` は iOS 自動ズーム防止のため `16px`）。

### UI・レイアウト・操作性禁止事項
- [ ] **画面上半分（0〜50%）での操作要素・クリック反応完全禁止**: `#viewport-upper` 内はボタン・リンク・スクロール・タップ反応を一切置かない（`pointer-events: none`）。**ボトムシートの暗幕（`#sheet-backdrop`）も含め**、上50%をタップしても絶対に反応・シート閉じさせてはならない（CSS `top: 50%` ＋ `app.js` `e.clientY < innerHeight * 0.5` の2重ガードを維持）。
- [ ] **Safari OK で PWA 時上部見切れ禁止**: `html, body` に `position: fixed; inset: 0; overflow: hidden;`、`index.html` に `viewport-fit=cover` ＋ `apple-mobile-web-app-status-bar-style="black-translucent"`、`#top-hud` に `padding-top: max(6px, env(safe-area-inset-top, 0px))` を必須とし、iPhone SE + SafeArea（上47px/下34px相当）でも 1px の上部・下部見切れを起こさない。
- [ ] **固定数UIでの微妙なスクロール禁止**: 固定4枠（パーティ/戦闘味方）・固定3枠（遺物）・設定画面（バックアップ＋2×2グリッド）・上50%全画面で、数pxだけスクロールバーが出たり見切れたりする崩れを絶対に許さない。
- [ ] **枠とスクロールバー被り禁止（2層ラッパー必須）**: スクロール領域は必ず外枠 `.scroll-frame`（`border` + `border-radius` + `overflow: hidden`）と内側 `.scroll-body`（`overflow-y: auto` + `scrollbar-gutter: stable`）の2層構造を使う。
- [ ] **動的要素増減によるズレ・見切れ禁止**: バフ増減・ダメージ数値増減・スキル名変化でユニットカードの高さや位置がガタつかないよう、固定トラック行（`.unit-buffs` 固定高、`.tnum` 等幅数字、バフ最大2チップ／3個以上は `1チップ + +N`）を維持する。
- [ ] **名前省略（`text-overflow: ellipsis` / `.slice()` 途中切断）禁止＆不自然な超短名乱発禁止**: キャラ名・敵名・技名・装備名・ステージ名を `...` や `.slice()` で途中切断しない。また画面に押し込むためだけの不自然な1〜2文字超短名を乱発しない。
- [ ] **ボタンのネスト禁止**: `<button>` や `role="button"` の中に別の `<button>` を入れない（カード本体ボタンとサブ操作ボタンは兄弟要素に分離）。

### 戦闘ルール絶対禁止事項
- [ ] **戦闘中の他画面移動禁止**: 戦闘中（`HS.Battle.isLocked() === true`）は下ナビの「編成」「育成」「冒険」「図鑑」タブをロック（`🔒` 表示＋移動拒否＋1行スリムトースト通知）し、「今回で停止」または「撤退」するまで他画面へ移動させない。
- [ ] **同時攻撃禁止**: 行動ゲージが同時に満タンになっても複数ユニットが同時に攻撃してはならない。必ず `readyQueue` から1体ずつ取り出し、`actionLockTimer`（`420ms / speed`）の間は次ユニットの行動開始をブロックする逐次攻撃を厳守すること。

### 3-2. バトルシステム全仕様（`js/engine/battle.js`, `js/ui/battle_view.js`, `js/ui/anim.js`）

- **基本進行**:
  - 戦闘速度 **1x / 2x / 3x** 切替（`HS.State.cycleSpeed()`）。
  - メイン冒険は **4エリア × 10ステージ = 全40ステージ**、各ステージ **全5WAVE**、敵 **1〜4体** 出現。
  - **非ボスWAVE乱入**: メイン冒険の非ボスWAVEで確率＋天井（`intruderPity`）により乱入敵が出現し、戦場中央の乱入警告バナー（`⚠ 乱入敵が出現！`）を発動。
  - **行動順4枠＆逐次攻撃・攻撃中ゲージ継続進行**:
    - 行動ゲージ上限 `1000`、攻撃演出ロック中（`actionLockTimer > 0`）も全生存ユニットのゲージが継続上昇して `readyQueue` に整列。
    - 行動実行はロック解除後に先頭1体ずつのみ（同時攻撃なし）。
    - 上部 `.turn-order-bar` は **先読み4枠固定均等グリッド**（行動中ユニットは先頭強調、右端切れゼロ）。
- **技構成・相性・状態効果**:
  - 全28キャラは **アクティブ3技**（19体）または **アクティブ2技＋常時パッシブ1種**（9体）。強さは `技1 < 技2 < 技3`（CD 0 → 2〜3 → 4〜5）、対象範囲は `単体 / 範囲（中心＋隣接） / 全体 / 自身 / 味方単 / 味方全`。
  - 6属性相性: 三すくみ（炎→風→水→炎：有利 **1.30倍** / 不利 **0.75倍**）、光⇔闇（相互有利 **1.25倍**）、無（等倍 **1.00倍**）。
  - 17種状態効果: バフ8（攻撃上昇・防御上昇・速度上昇・会心上昇・継続再生・防護壁・挑発・反撃構え）、デバフ4（攻撃低下・防御低下・速度低下・脆弱）、状態異常5（火傷・猛毒・気絶・沈黙・凍結）。
  - ユニットカード上のバフ帯は1〜2個なら1〜2チップ、3個以上は「1チップ＋`+N`」（例 `攻↑2 +3`）で横切れゼロ。
- **自動周回・今回で停止・自動売却・リザルト・ログ・4指標DPS**:
  - メイン冒険＆指名手配で **自動周回** 対応。戦闘中 `#context-bar` は `[速度]` `[自動周回 OFF / 今回で停止 / 停止予約済]` `[⚙ 自動売却]` `[撤退]` の無駄ゼロ4ボタン構成（非周回モードは3ボタン）。
  - **自動売却**: 獲得時に指定品質以下（`39/69/89/99以下`）の未保護装備を自動換金。**品質100「👑極」はデフォルトで完全保護**。一括売却にも対応。
  - **通常リザルト／周回リザルト分離**: 上50%に4人のミニ与ダメ貢献バー（`scaleX`・実数・%・MVP王冠）＋獲得素材・装備ドロップ詳細（`👑極100`強調）・別働隊帰還サマリを高密度表示。
  - **戦闘ログ（下50%「行動ログ」タブ）**: 最大100件を上詰め正順表示、最下部付近では自動追従、上にスクロールした時だけ本文に被らない「▼最新へ」ピルを表示。
  - **周回累計4指標DPS（下50%「戦果DPS」タブ）**: `与ダメ / 被ダメ / 与回復 / 被回復` の4指標を自動周回中ずっと累計集計し、`scaleX` バーで軽量描画。
  - **戦術確認（下50%「戦術確認」タブ）**: 敵・味方詳細、発動シナジー、別働隊進行状況を確認可能。
- **GPU演出最適化（`js/ui/anim.js`）**:
  - 単一 `requestAnimationFrame` ループ（タブ非表示時自動一時停止）。
  - ダメージポップアップは **28ノード固定プール** で生成・破棄ゼロ、表示座標を `.unit-card` 内に厳密クランプしてメタバーと非重複。
  - スキルカットイン帯は敵行と味方行の間の専用スリム帯（`computeSeamTopPx()`）に配置しユニット名と非重複。

   - `自動再出撃 ON/OFF` に対応し、OFFで帰還後は一時停止状態（`paused: true`）になり、任意のタイミングで「再開」可能。
2. **1対1 控えリンク（4枠）**:
   - 出撃4人それぞれに控えキャラ1人を1対1で紐づけ。
   - 控えキャラのロールに応じた固有パッシブ（盾:`開幕壁15%・防+12%` / 攻:`攻+12%・追撃15%` / 援:`初期ゲ+25%・速+10%` / 癒:`WAVE回復15%・耐+15%`）に加え、**同属性一致（HP+5%・攻+5%）**・**同種族一致（防+6%・会心+4%）** ボーナスが発生。
   - さらに**控えリンク4人もパーティ編成シナジー（全37種）の人数カウントに合算**される。
3. **多部隊リレー総力戦（3部隊リレー・全3難度）**:
   - 1軍→2軍→3軍（各最大4人・重複不可・自動編成ボタン付）を事前編成し、3連ボス戦へ挑戦。部隊が全滅しても次部隊へ自動バトンタッチして継続戦闘。

1. **属性順**: `炎(fire)` → `水(water)` → `風(wind)` → `光(light)` → `闇(dark)` → `無(none)`

   - **複合種族ルール**: 配列を上記種族順で正規化し、`[第1種族]` 単一の直後に `[第1種族, 第2種族]` を辞書順配置（例: `人間` → `人間・竜` → `人間・魔物` → `竜` …）。
3. **ロール順**: `タンク(tank)` → `ディーラー(dealer)` → `サポーター(supporter)` → `ヒーラー(healer)`
4. **五十音順**: `kana` フィールドの `localeCompare(..., 'ja')`（装備インベントリ時はさらに品質降順）。

## 4. 次回開発の進め方ルール（必須ワークフロー）

次回セッションで機能追加・修正・改名を行う際は、必ず以下の手順で進めること。

1. **トークン節約・ピンポイント読込**:
   - 最初に `docs/HANDOFF_SPEC.md`（本書）と `docs/CODE_MAP.md` を読む（固有名詞・データ変更時は `docs/DATA_CATALOG.md` も読む）。
   - コードを読む際はファイル丸読みを避け、`CODE_MAP.md` に記載の**該当関数・該当行番号のみ**を部分読込して編集する。
2. **既存仕様＆禁止事項の完全保護**:
   - 変更前後で本書の「第2章 絶対厳守の禁止事項一覧」および「第3章 実装済み仕様」を1項目も壊していないか確認する。
   - 総ファイル数が 100 ファイル未満（余裕を持って維持）であることを確認する。
3. **キャッシュ更新**:
   - JS / CSS / HTML / アセットを1行でも変更したら、必ず `sw.js` の `CACHE_NAME`（現在 `'hachamecha-sekai-v3'`）をインクリメント（例 `'hachamecha-sekai-v4'`）する。新規ファイル追加時は `PRECACHE_ASSETS` と `index.html` の読込順にも漏れなく追記する。
4. **実ブラウザ多解像度テストプレイ（必須）**:
   - 構文チェック（`node --check`）＋禁止語句スキャンに加え、実ブラウザ（Playwright 等）で以下の全条件を検証する:
     - **iPhone SE（375×667）**
     - **iPhone SE + SafeArea（375×667, top:47px / bottom:34px 相当エミュレーション）**
     - **iPhone 15 Pro（393×852）**
     - **iPhone 15 Pro + SafeArea（393×852, top:59px / bottom:34px 相当）**
     - **大画面（430×932）**
     - **`file://` 直開き**（コンソールエラー・未キャッチ例外ゼロ）
   - 上50%クリック無反応、見切れゼロ、枠とスクロールバー非重複、文字省略ゼロ、戦闘中タブロック、セーブ復元を確認。
5. **洗い出し → 改修 → 再テストプレイ**:
   - スクリーンショット目視＆DOM矩形計測で不具合や違和感を洗い出し、修正後に再度テストプレイしてゼロ不具合を確認する。
6. **`docs/` 4資料の最新化**:
   - 変更完了後、必ず `docs/CODE_MAP.md`・`docs/DATA_CATALOG.md`（機械スキャンで正確な行番号を再生成）・`docs/HANDOFF_SPEC.md`・必要に応じ `docs/NEXT_PROMPT.md` を最新状態へ同期し、一時スクリプトを完全削除して終了する。
